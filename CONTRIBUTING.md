# Contributing to HireTitan

## Setup after cloning

```bash
git config core.hooksPath .githooks   # enables the commit-msg format check
```

## Branches

- **`master`** is the main branch. It must always be releasable.
- Every feature gets its own branch cut from `master`, named after its spec folder:
  ```bash
  git switch master
  git pull --ff-only
  git switch -c 001-setup-and-profile
  ```
- Work, test and commit on the feature branch (one commit per task).
- When the feature's tests and quality gates pass, push the branch and open a **GitHub pull request into `master`**. Merge only after review and green checks.
- Never commit feature work directly on `master`.

## Commit message format

```
[<branch> - <feature>] - If applied this commit will <change>
```

| Part | Meaning | Example |
|---|---|---|
| `<branch>` | Exact current branch name | `001-setup-and-profile` |
| `<feature>` | Short name of the work in this commit (Spec Kit task ID first when there is one) | `T012 resume upload` |
| `<change>` | Finishes the sentence: lowercase imperative verb, no trailing period | `add PDF and DOCX resume upload with a 5 MB size limit` |

Examples:

```
[master - project skeleton] - If applied this commit will add the repository skeleton with Spec Kit, constitution and commit conventions
[001-setup-and-profile - T012 resume upload] - If applied this commit will add PDF and DOCX resume upload with a 5 MB size limit
[001-setup-and-profile - T013 resume upload tests] - If applied this commit will test FR-004 rejection of unsupported file types
```

An optional body (blank line after the subject) explains why and lists the requirement IDs covered. Merge, revert and fixup commits generated by git are exempt. The `.githooks/commit-msg` hook rejects anything else; fix the message rather than using `--no-verify`. Claude Code users can run `/commit`, which follows these rules.

## Feature workflow (Spec Kit)

`/speckit-specify` → `/speckit-clarify` → `/speckit-plan` → `/speckit-tasks` → `/speckit-analyze` → `/speckit-implement`

Each step's output is reviewed before the next. Implementation is test-first: write the task's tests (named after requirement/scenario IDs), watch them fail, make them pass, refactor.

## Privacy

Never commit personal data: real resumes, `.env`, API keys, or anything under `docs/private/`. Fixtures and demo data are synthetic.
